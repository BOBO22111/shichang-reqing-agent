# 市场热度情绪智能体

全市场热度排行 · 赛道冷热识别 · 资金轮动监测

> 币安 Agent 参赛作品 · 方向：数据分析

---

## 一、这个项目解决什么问题

看单个币涨了多少，说明不了市场热不热。

同样是涨 10%，巨量资金推动的上涨和几笔小单拉起来的上涨，完全是两回事。
只看涨跌幅做排行，结论很容易失真。

这个项目做的是**横截面分析**：把全市场 300 多个永续合约放在一起比较，回答四个问题：

1. **哪个币真的热？** —— 用涨跌幅、成交额、换手强度、波动幅度四项合成热度分数
2. **钱堆在哪个方向？** —— 按赛道聚合，找出热门赛道与冷门赛道
3. **哪些币在被抛？** —— 跌幅明显且成交活跃、换手偏高的币种
4. **钱在往哪流？** —— 资金是在从中小币撤向大饼，还是从大饼铺向中小币

最后把整个市场归入**狂热 / 活跃 / 中性 / 低迷 / 恐慌**五档情绪之一。

## 三、核心算法（简版）

### 热度分数（0–100）

```text
热度分数 = 100 × (0.30 × 涨跌幅排名 + 0.30 × 成交额排名
                + 0.20 × 换手强度排名 + 0.20 × 波动幅度排名)
```

三项关键处理：

- **排名用全市场百分位**，所以结果不受当期行情绝对水平影响
- **成交额先取 `log10` 再排名**，否则大币与小币的量级差距会让分布失去区分度
- **换手强度先裁剪到 P5–P95 再排名**，避免极端离群值把分布压扁

当某个分项在数据源里不存在时，该分项权重按比例分摊给其余分项，**不会填假数**。

### 情绪指数与五档

```text
情绪指数 = 0.40 × 上涨家数占比得分
         + 0.30 × 成交额加权涨跌幅得分
         + 0.30 × 高热度币种占比得分
         − 避险扣分（大饼成交额占比过高时扣分）
```

| 档位 | 指数区间 |
|---|---|
| 狂热 | ≥ 78 |
| 活跃 | 65 – 78 |
| 中性 | 45 – 65 |
| 低迷 | 30 – 45 |
| 恐慌 | < 30 |

阈值集中在 `heat-engine.js` 顶部的常量里，调整不需要翻代码。

### 资金轮动

```text
小币组   = 按成交额排序的第 21 – 100 名（避开头部大币）
超额表现 = 大饼涨跌幅 − 小币组成交额加权涨跌幅

超额表现 > +1.5 个百分点  →  资金回流大饼
超额表现 < −1.5 个百分点  →  资金轮动到小币
其余                       →  轮动平稳 · 方向不明
```

并用「大饼成交额占比的会话内变化方向」做二次确认。

## 四、数据来源与口径要点

- 数据来自**各大平台公开行情接口**（永续合约口径），无需密钥
- 不接入交易权限、不保存私钥、不执行任何下单、不读取任何账户信息

**三个必须说明的口径问题：**

| 问题 | 处理方式 |
|---|---|
| 接口不提供流通量，换手率算不出来 | 改用**换手强度 = 24 小时成交额 ÷ 持仓量美元值**，并在页面标注 |
| 备用数据源不提供 24 小时最高/最低价 | 波动幅度列留空并标注「该数据源不提供」，**不估算** |
| 持仓量变化需要两个时间点 | 把上一次快照存在**浏览器本地存储**，首次打开时提示等待下一次刷新 |

**统计范围：** 只统计 USDT 计价永续合约，排除稳定币互兑对，
并剔除 24 小时成交额低于 20 万美元的僵尸合约（页面会显示实际参与统计的合约数量）。

**数据真实性：** 接口失败时显示明确的中文失败原因，
**不会用演示数据或固定数值顶替，也不会把演示数据描述成实时数据**。

## 五、目录结构

```text
├─ index.html              页面骨架
├─ styles.css              主题与布局
├─ favicon.svg
├─ sectors.js              内置「币种 → 赛道」映射表
├─ market-snapshot.js      快照归一化与数值格式化
├─ heat-engine.js          全部算法（纯计算，无网络请求）
├─ history-tracker.js      会话内快照留存与环比
├─ data-source.js          浏览器直连取数
├─ api-client.js           取数通道选择与自动兜底
├─ chart.js                自绘图表（气泡图 + 迷你 K 线）
├─ app.js                  页面渲染与交互
├─ functions/              云端接口代理
│  ├─ _data.cjs            取数与统一换算
│  ├─ heat.cjs             /api/heat
│  └─ market.cjs           /api/market
├─ netlify.toml            部署与路由配置
└─ package.json
```

**为什么是扁平结构：** 除 `functions/` 外所有文件都平铺在根目录。
因为 GitHub 网页版上传框只接受单独的文件，拖文件夹会被忽略 ——
扁平结构下 `Ctrl+A` 全选出来的全是文件，一次就能传完。

## 六、部署

支持两种方式，同一套代码都能跑：

| 方式 | 效果 |
|---|---|
| 拖拽上传（Netlify Drop 等） | 云端函数不运行，页面**自动切换浏览器直连**，功能完整 |
| 连接 Git 仓库自动部署 | `functions/` 生效，额外获得服务端缓存与统一错误处理 |

两种方式下页面顶部的「取数通道」会如实显示当前实际使用的那条通道。

详见《上传到Netlify-操作步骤.md》。

## 九、风险提示

本页面仅用于数字资产市场风险观测与数据分析，**不构成投资建议**。

热度分数衡量的是当期资金参与程度，**不是价格预测**；情绪档位描述的是当前截面状态，
五档之间可能快速切换；资金出逃识别是横截面统计，不构成任何方向性判断。

市场有风险，投资需谨慎。任何投资决策应结合个人风险承受能力、资金状况与投资目标独立判断，
必要时咨询持牌专业机构。过往表现不预示未来收益。
