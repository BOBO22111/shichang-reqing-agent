# 市场热度情绪（shichang-reqing）

看单个币涨了多少，说明不了市场热不热。

同样是涨 10%，巨量资金推动的上涨和几笔小单拉起来的上涨，完全是两回事。只看涨跌幅做排行，结论很容易失真。本技能做的是**横截面分析**：把全市场的合约放在一起比较，一次性回答四个问题 —— 哪个币真的热、钱堆在哪个方向、哪些币在被抛、钱在往哪流。

## 数据来源（官方公开入口，无需密钥）

本技能提供四条数据通道，全部使用**公开**数据、都不需要 API 密钥、都不涉及账户权限：

| 通道 | 官方来源 | 特点 |
|---|---|---|
| `--skill`（官方技能） | 官方技能市场 [binance/binance-skills-hub](https://github.com/binance/binance-skills-hub) 的 `binance` 技能：调用其驱动的命令行工具 `binance-cli` 取全市场行情（Market 区块，无需鉴权） | 全市场现货快照；官方 CLI 默认入口不可达时改用官方为「仅公开行情」提供的独立入口（请求仍由官方 CLI 发起）；未安装 `binance-cli` 时自动回退到 `--live` 同一端点，并打印官方安装命令 |
| `--official`（推荐） | [binance/binance-public-data](https://github.com/binance/binance-public-data) → `data.binance.vision` 的合约 K 线 + 合约指标文件 | **合约口径 + 附带持仓量**；结果可复现；币种名单从实时接口动态获取 |
| `--live` | [binance/binance-spot-api-docs](https://github.com/binance/binance-spot-api-docs) 记载的公开行情入口 `data-api.binance.vision` | 一次请求拿全市场现货快照（`ticker/24hr` 不带 symbol） |
| 默认（实时多平台） | 多平台公开行情接口（合约 + 链上） | 与网页版完全一致的口径，打开即用 |

需要账户或交易类能力时，可另外装载官方技能市场
（`npx skills add https://github.com/binance/binance-skills-hub`），本技能不与之冲突。

## 什么时候用这个技能

在下面这些情况下调用它：

- 用户问「现在市场热不热」「情绪怎么样」「是牛市还是熊市气氛」
- 用户想知道哪些币最热、哪些赛道在被资金关注
- 用户想找「跌得狠但成交还很大」的币（资金出逃嫌疑）
- 用户想知道钱是从小币撤向大饼，还是从大饼铺向小币

不要在下面这些情况下用它：用户要求下单/交易（本技能只读公开行情，不能下单）、用户要求预测未来价格（本技能只描述当期截面状态，不做预测）、用户问的是单个币的成交结构（那是「成交结构拆解」类技能的活）。

## 前置条件

- 需要 Node.js 18 或更高版本（零第三方依赖，不需要 API 密钥）
- 需要能访问交易所公开行情接口的网络环境

## 怎么运行

本技能就是一条命令，在技能所在项目的根目录执行：

```sh
node agent.mjs [--official] [--live] [--skill] [--json]
```

常用示例：

```sh
# 默认：实时多平台（合约口径，与网页版完全一致）
node agent.mjs

# 官方公开数据：合约口径 + 持仓量，结果可复现（推荐）
node agent.mjs --official

# 只看成交额前 200 个合约（默认 120，最大 400）
node agent.mjs --official --top 200

# 只看指定的几个币
node agent.mjs --official --symbols BTC,ETH,SOL

# 指定历史日期（UTC）；不指定时自动取最近一个已发布文件的日期
node agent.mjs --official --date 2026-09-11

# 官方公开行情接口（全市场现货快照，一次拿全）
node agent.mjs --live

# 官方技能通道：调用 binance-cli（未安装时自动回退并给安装命令）
node agent.mjs --skill

# 自然语言也可以
node agent.mjs "看看现在市场热不热"

# 输出 JSON，便于程序解析
node agent.mjs --official --json

# 查看 / 清空「与上次运行对比」的基线
node agent.mjs --status
node agent.mjs --reset
```

参数说明：

| 参数 | 含义 |
|---|---|
| `--official` | 官方公开数据通道（历史文件，**推荐**，可复现且带持仓量） |
| `--live` | 官方公开行情接口（全市场现货快照，一次请求拿全） |
| `--skill` | 官方技能通道：优先调用 `binance-cli`；主站入口不可达时自动改用官方公开行情专用入口；未安装时回退到 `--live` 同一端点 |
| `--top N` | 官方通道参与分析的合约数量上限，默认 120，最大 400 |
| `--symbols A,B,C` | 官方通道只分析这些币种（优先于动态取名单） |
| `--date YYYY-MM-DD` | 官方通道的 UTC 日期，默认自动取最近一个已发布文件的日期 |
| `--concurrency N` | 官方通道的并发下载数，默认 10 |
| `--spot` / `--perp` | 现货 / 永续合约（默认永续；`--live` 与 `--skill` 只有现货） |
| `--json` | 输出 JSON（进度信息写到 stderr，stdout 只有 JSON） |
| `--status` / `--reset` | 查看或清空「与上次运行对比」的基线 |

### 四条通道怎么选

| 场景 | 用哪条 | 命令 |
|---|---|---|
| 想立刻看到市场整体状态 | 默认实时多平台 | `node agent.mjs` |
| 想复现某个日期的市场截面 | **官方公开数据** | `node agent.mjs --official --date 2026-09-11` |
| 想要带持仓量的合约口径 | **官方公开数据** | `node agent.mjs --official` |
| 想覆盖更多币种 | 官方公开行情接口 | `node agent.mjs --live`（一次拿全市场现货） |
| 已按官方技能装好 binance-cli，想走官方工具 | **官方技能** | `node agent.mjs --skill` |

### 关于官方技能通道（`--skill`）

- **怎么装**：该通道调用的是官方技能市场 `binance` 技能所驱动的命令行工具，安装命令见官方仓库 `binance/binance-cli`。
  该仓库的 **Windows 构建只发布在 `v2.0.0`**（之后的版本只有 macOS 与 Linux 包）。装好后命令名为 `binance-cli`；
  也可以用环境变量 `BINANCE_CLI_PATH` 直接指定可执行文件的完整路径。
- **网络**：官方 CLI 的行情命令默认访问官方主站域名。若该域名在当前网络下不可达，本技能会自动改用官方为
  「仅需公开行情」提供的独立入口 —— **请求仍由官方 CLI 发起、返回的仍是官方数据**，输出里会如实标注走的是哪一条。
- **没装也能用**：本技能会回退到 `--live`（同一份官方公开行情数据），并打印官方安装命令，不影响出结论。

### 关于官方通道的「币种名单是怎么来的」

官方公开数据仓库只按「币对」存放文件，**没有目录列举接口**，拿不到完整币种清单。本技能的做法是：

1. 先从实时接口动态要一份「当前真实在交易的合约」名单，按 24 小时成交额排序；
2. 再按这份名单逐个去官方仓库取对应文件，拼成全市场快照。

几个如实披露的细节：

- 名单来源会打印出来（综合平台的合约全市场快照；该接口不可用时退回官方公开行情接口的现货快照；再不可用才用**内置清单**，并明确标注「已退回内置清单」）
- 官方仓库对低价币使用「面值币」代码（例如 `1000PEPEUSDT`），本技能会自动对应，并在输出的数据质量区说明有几个币走了这条对应
- 官方仓库里没有文件的币（例如只在其他平台上线的合约）会如实计入「未纳入」的数量与示例，**不会拿别的数据顶替**
- 成交额低于 20 万美元的僵尸合约会被剔除，口径与网页版一致

## 输出怎么读

文本模式输出六块内容：

1. **市场情绪** —— 五档档位 + 情绪指数（0–100）+ 档位说明
2. **全市场概览** —— 参与统计合约数、成交额、持仓量、涨跌家数、成交额加权涨跌、涨跌中位数、大饼成交额占比、高热度币种占比
3. **热度最高 / 最低各 10 个币** —— 含所属赛道、热度分数、24 小时涨跌、成交额、换手强度
4. **资金出逃警示** —— 同时满足跌幅、成交额排名、换手强度排名三条条件的币，并标注持仓量是否确认下降
5. **资金轮动** —— 大饼与小币组的超额表现、大饼成交额占比及其会话内变化、结论是否被占比变化确认
6. **赛道冷热 + 官方通道独有维度 + 数据质量** —— 热门/冷门赛道、官方指标文件附带的资金方向维度、解析成功与未纳入的币数

JSON 模式（`--json`）的关键字段：

| 字段 | 说明 |
|---|---|
| `ok` | 是否给出了结论（取到数据即为 true） |
| `source` | 实际使用的通道：`official` / `live` / `skill` / `realtime` |
| `requestedSource` | 用户原本请求但被回退的通道（例如请求了 `--skill` 但没装 CLI，这里会是 `skill`） |
| `sourceLabel` / `dataUrl` | 通道的中文说明 / 实际请求的官方地址（便于复核） |
| `official` | 官方通道专用：日期、名单来源、解析成功数、未纳入数、被剔除数、面值币对应数 |
| `coverage` | 参与统计的币数、其中有持仓量的数量、有波动幅度的数量 |
| `mood` | 情绪档位：`level` / `key`（`mania` 狂热 · `active` 活跃 · `neutral` 中性 · `quiet` 低迷 · `panic` 恐慌）/ `name` / `score` / `desc` / `parts`（三个分项与避险扣分） |
| `market` | 全市场统计：家数、广度、加权涨跌、中位数、总成交额、总持仓量、大饼占比等 |
| `topHeat` / `bottomHeat` | 热度最高 / 最低各 10 个币的明细 |
| `sectors` | 热门/冷门赛道（前三）、归入「其他」的成交额占比 |
| `outflow` | 资金出逃嫌疑币种（含评分与文字理由） |
| `rotation` | 资金轮动：方向键 `dir`（`to-btc` / `to-alt` / `flat`）、超额表现 `rs`、大饼占比及变化、是否 `confirmed` |
| `officialExtras` | 官方指标文件附带的资金方向维度（主动买卖量比、大户多空比）—— **不参与热度分数与情绪档位**，仅作参考 |
| `rules` | 本次使用的全部阈值（权重、出逃条件、轮动阈值、热度线、平盘死区、赛道最小样本数） |
| `warnings` | 如实披露的口径提醒（例如「本通道是现货口径，没有持仓量」） |

退出码：`0` 表示给出了结论，`1` 表示取数失败（例如官方文件取不到、网络不通）。

## 算法口径（回答用户追问时要能解释清楚）

### 热度分数（0–100）

```text
热度分数 = 100 × (0.30 × 涨跌幅排名 + 0.30 × 成交额排名
                + 0.20 × 换手强度排名 + 0.20 × 波动幅度排名)
```

三项关键处理：

- **排名用全市场百分位**，所以结果不受当期行情绝对水平影响
- **成交额先取 `log10` 再排名**，否则大币与小币的量级差距会让分布失去区分度
- **换手强度先裁剪到 P5–P95 再排名**，避免极端离群值把分布压扁

当某个分项在数据源里不存在时（例如现货通道没有持仓量，换手强度算不出来），该分项的权重按比例分摊给其余分项，**不会填假数**。

### 情绪指数与五档

```text
情绪指数 = 0.40 × 上涨家数占比得分
         + 0.30 × 成交额加权涨跌幅得分
         + 0.30 × 高热度币种占比得分
         − 避险扣分（大饼成交额占比 ≥ 60% 扣 8 分、≥ 70% 再扣 6 分）
```

| 档位 | 指数区间 |
|---|---|
| 狂热 | ≥ 78 |
| 活跃 | 65 – 78 |
| 中性 | 45 – 65 |
| 低迷 | 30 – 45 |
| 恐慌 | < 30 |

「高热度币种」指热度分数 ≥ 70 的币。涨跌幅在 ±0.1% 以内视为平盘，不计入上涨也不计入下跌。

### 换手强度（为什么不用换手率）

公开行情接口不提供流通量与流通市值，**标准口径的换手率算不出来**。本技能改用：

```text
换手强度 = 24 小时成交额 ÷ 持仓量美元值
```

衡量的是资金周转快慢。现货通道没有持仓量，该列留空并如实说明。

### 资金出逃的三条横截面条件

```text
跌幅 ≤ −4.5% 且 成交额排名进全市场前 40% 且 换手强度排名进全市场前 40%
```

再加两条增强：会话内持仓量下降超过 3% 时加分并标注「已确认」；只有一次运行、拿不到基线时标注「待下一次运行确认」（**不会假设持仓量下降**）。

### 资金轮动

```text
小币组   = 按成交额排序的第 21 – 100 名（避开头部大币）
超额表现 = 大饼涨跌幅 − 小币组成交额加权涨跌幅

超额表现 > +1.5 个百分点  →  资金回流大饼
超额表现 < −1.5 个百分点  →  资金轮动到小币
其余                       →  轮动平稳 · 方向不明
```

并用「大饼成交额占比的会话内变化方向」做二次确认：方向一致才算「已确认」，不一致会如实标为未确认。

### 赛道分类

赛道来自项目内置的「币种 → 赛道」映射表（11 个赛道 + 「其他」兜底），公开接口不提供赛道字段。未收录的币种归入「其他」，其成交额占比会在输出里如实显示。

### 诚实边界（回答用户时必须如实转达）

- 热度分数衡量的是**当期资金参与程度，不是价格预测**；情绪档位描述的是当前截面状态，五档之间可能快速切换
- 资金出逃识别是横截面统计，不构成任何方向性判断
- 官方通道的涨跌幅是**跨日口径**（前一日最后一根 K 线收盘 → 当日最后一根 K 线收盘）；前一日文件缺失时会退回当日开盘价并明确标注
- 官方通道持仓量取自官方指标文件的最后一条（5 分钟粒度）
- 接口失败或超时时给出明确的中文失败原因，**不会用演示数据或固定数值顶替**
- 不同通道的口径不同（官方合约 / 官方现货 / 多平台合约），**跨通道的数字不能直接对比**，输出里会标明当前口径

## 安全与合规

- 只读取交易所**公开行情数据**，不登录、不绑定、不读取任何账户信息
- 不需要也不接受任何 API 密钥
- **不执行任何交易操作**，没有下单能力
- 输出仅为数据统计结果，不构成投资建议。转达给用户时应保留这一声明。
